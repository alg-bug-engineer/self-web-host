# 儿童 AI 素养不是提示词课：用“输入—输出—风险—责任”搭一套课程框架

生成式 AI 进入家庭以后，很多课程的第一反应是教孩子写提示词。

这当然有用。但如果一门儿童 AI 课的核心内容只是“角色、任务、背景、格式”四段式提示词，它解决的更多是操作熟练度，不是 AI 素养。

一个孩子可以很快学会让模型写故事、做图片、解释题目，同时依然回答不了下面几个问题：

- 模型拿到了什么输入？
- 输出为什么可能出错？
- 哪些结论必须再核验？
- 哪些信息不应该交给模型？
- 关闭工具以后，最终判断是谁做的？

我最近在试做一套面向 8—14 岁孩子和家长的 AI 素养实践课。与其从工具列表开始，我更愿意把课程看成一个需要设计接口、约束、反馈和故障处理的系统。

## 先定义课程输出，而不是先选工具

做系统设计时，我们不会因为某个中间件最近很热门，就先把它塞进架构图。课程也一样。

先装一批 AI App，再围绕它们编课，最后很容易变成产品功能培训。模型版本一换，课程的一半内容就过时了。

更稳定的做法，是先定义学习者最终需要形成什么能力。

UNESCO 的学生 AI 能力框架给出了一个可借鉴的二维结构：横向包含“以人为中心的心态、AI 伦理、AI 技术与应用、AI 系统设计”四个维度，纵向按照“理解、应用、创造”三个层次递进。

这个结构有一个很重要的信号：AI 素养不只是技术知识，也不只是安全教育。它同时包含人的主体性、伦理判断、技术理解和系统创造。

因此，我给课程定义的不是“会使用三个模型”，而是下面四个输出：

1. 能描述一个 AI 功能的输入、输出和基本任务。
2. 能发现输出中的不确定性，并知道什么时候要查来源。
3. 能把一个任务拆成人与 AI 分别承担的步骤。
4. 能在隐私、安全和责任边界内完成一次亲子项目。

工具只是运行环境，不是课程目标。

## 用四个字段描述任何 AI 功能

面对 8—14 岁孩子，我不打算从神经网络公式开始，也不想用“AI 像一个聪明小伙伴”来解释。

前者门槛太高，后者又容易造成拟人化误解。

一个更容易观察的起点，是给所有 AI 功能套上四个字段：

| 字段 | 要问的问题 | 示例：相册分类 |
|---|---|---|
| 输入 | 系统拿到了什么？ | 图片像素 |
| 输出 | 系统给出了什么？ | “猫”标签 |
| 风险 | 它可能怎样出错？ | 把玩具猫认成真猫 |
| 责任 | 谁负责检查和处理？ | 孩子与家长 |

推荐系统、语音识别、生成式问答和图像生成都可以放进这个框架。

区别只是输入输出形式、错误概率和出错后的影响不同。

推荐错一首歌，代价通常很低；把健康信息、考试结论或涉及他人的指控判断错，后果完全不同。孩子需要理解的不是抽象的“AI 有风险”，而是风险与具体任务相关。

这也是我把“谁来检查”单独列成一列的原因。系统不会因为输出流畅，就自动获得决策权。

## 把 12 节课设计成一条能力链

基于“理解—应用—创造”的递进，我暂时把四周课程拆成下面这条链路。

### 第一周：看见 AI，也看见它会犯错

1. AI 到底是什么：从生活里的预测开始。
2. AI 为什么会回答问题：数据、模式与生成。
3. AI 为什么会一本正经地犯错。

这一周不要求孩子注册新工具。先从相册分类、输入法联想、推荐列表这些已有体验出发，建立输入、模式、输出和检查者的概念。

### 第二周：学会协作，而不是把任务交出去

4. 把问题说清楚：背景、目标和限制。
5. 把大任务拆成可以检查的小步骤。
6. 人和 AI 分别擅长什么。

提示词会在这一周出现，但它被放在“问题定义”里，而不是包装成某种万能咒语。

### 第三周：把验证变成固定流程

7. 验证 AI：来源、反例与交叉检查。
8. 用 AI 完成一次小型研究。
9. 亲子共创：从想法到可以展示的作品。

重点不只是查一个链接，而是保留“最初答案—发现问题—修改过程—最终判断”这条证据链。

### 第四周：完成项目，也建立家庭规则

10. 隐私、版权与虚假内容。
11. 不把聊天机器人当成答案和情感替代。
12. 制定家庭 AI 使用公约并完成项目答辩。

隐私提醒不会等到第四周才出现。它从第一节课就作为每次任务的最低边界重复出现；第四周只是把零散规则整理成一份家庭公约。

## 评价不能只看“生成得漂不漂亮”

生成式 AI 很容易制造一种评价错觉：作品越完整、画面越漂亮，能力似乎越强。

但生成结果可能主要反映模型能力，也可能来自模板复制。仅看最终作品，很难判断孩子做了哪些思考。

我更倾向于把每个任务的评价拆成五项：

- 问题：孩子能否说清楚自己要解决什么？
- 分工：哪些步骤交给 AI，哪些必须由人完成？
- 证据：重要结论依据什么？
- 修改：孩子发现并修正了什么问题？
- 反思：如果重做一次，他会改变什么？

这很像工程系统的可观测性。最终输出只是一个状态，真正帮助我们定位问题的是过程日志。

课程作业也需要“日志”，但不应该变成收集孩子隐私的日志。它可以只记录匿名的任务描述、提示变化、来源和修改理由，不记录姓名、学校、住址、账号、私人聊天或清晰面部。

## 儿童场景必须把安全当成架构约束

UNICEF 2025 年更新的《Guidance on AI and Children》提出了十项儿童中心 AI 要求，其中包括安全、数据与隐私保护、公平、透明与问责、儿童福祉和面向未来的能力准备。

教育部等五部门 2026 年印发的《“人工智能+教育”行动计划》也明确提出“育人为本、素养为先、应用导向、智能向善”，并要求建立教育应用的安全防护、测评、监测和风险响应机制，防范隐私泄露、伪造诈骗、学术造假等问题。

这些文件不是某一门课程有效的实验结论，但它们为课程边界提供了依据。

落到家庭任务里，我把最低约束写得很具体：

- 不要求孩子上传真实姓名、学校、住址和联系方式。
- 不把私人聊天记录、正脸照片和可识别作品元数据当作作业素材。
- 不用 AI 输出替代医疗、法律、财务等高风险专业判断。
- 不把聊天机器人当成稳定、可信的情感关系替代。
- 知识类结论需要检查来源；找不到可靠依据时允许保留“不确定”。
- 家长知道孩子用了什么工具、完成了什么任务，并参与风险较高的环节。

安全不是最后一节课的“注意事项”，而是整个课程运行时都存在的约束。

## 第一项亲子任务：家庭 AI 足迹

课程的第一个任务很简单：家长和孩子一起找出一天中出现的五个 AI 功能。

每个功能只填五项：

| 场景 | 输入了什么 | 输出了什么 | 可能怎样出错 | 谁来检查 |
|---|---|---|---|---|
| 相册分类 | 图片像素 | “猫”标签 | 玩具猫被认成真猫 | 孩子和家长 |
| 1 |  |  |  |  |
| 2 |  |  |  |  |
| 3 |  |  |  |  |
| 4 |  |  |  |  |
| 5 |  |  |  |  |

这个任务不需要打开新工具，也不需要上传任何数据。

它想训练的是一种观察习惯：不要只看到“AI 给了我一个答案”，还要看见这个答案在完整任务链路中的位置。

## 一个月试运行真正要验证什么

这套课程现在还是试运行，不应该先假设它一定有效。

一个月里，我更想验证下面几件事：

1. 8—10 岁、11—12 岁和 13—14 岁是否需要明显不同的解释和任务难度？
2. 家长能否每周拿出稳定时间共同完成任务？
3. 孩子能否从“给我答案”逐步转向主动找错误、找来源？
4. 哪些隐私和情感依赖风险最容易被家庭忽略？
5. 哪些内容适合公开科普，哪些需要在小范围作业和答疑中完成？

比起一开始就承诺“让孩子赢在 AI 时代”，我更愿意先留下真实任务、真实反馈和可复查的修改记录。

如果你家里也有正在使用生成式 AI 的孩子，可以在评论区只回答一个问题：你最担心孩子怎样使用 AI？

请不要留下孩子的姓名、学校、账号或其他可识别信息。
